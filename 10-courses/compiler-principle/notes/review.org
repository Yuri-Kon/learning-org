* 第0讲：编译器全局地图

流水线:

1. 源程序
2. 词法分析：字符流 -> token 序列
3. 语法分析：token 序列 -> 语法树/抽象语法树
4. 语义分析：类型检查、作用域检查、声明使用检查
5. 中间代码生成：AST -> 三地址码
6. 代码优化：等价变换，让代码更快或更小
7. 目标代码生成：三地址码 -> 汇编/机器代码


*词法分析管“单词”，语法分析管“句子结构”，语义分析管“意思是否合理”，中间代码负责统一表示，优化负责变好，代码生成负责落实到机器。*

比如:

#+begin_src c
  position = initial + rate * 60;
#+end_src

词法分析之后大概是:

#+BEGIN_EXAMPLE
<id, position> <=> <id, initial> <+> <id, rate> <*> <num, 60> <;>
#+END_EXAMPLE

语法分析会识别出这是一个赋值语句，右边是一个表达式，并且 ~*~ 的优先级高于 ~+~ 。

中间代码可能是：

#+BEGIN_EXAMPLE
t1 = rate * 60
t2 = initial + t1
position = t2
#+END_EXAMPLE

后面优化可能发现某些临时变量可以删除，代码生成会分配寄存器并产生目标代码。

* 第1讲：绪论

** 编译程序是什么

编译程序的功能是： *把源语言程序翻译成目标语言程序* 。

例如:

#+BEGIN_EXAMPLE
C / Java / Pascal 源程序 -> 汇编代码 / 机器代码 / 字节码
#+END_EXAMPLE

常见的区分：

| 名称     | 含义                       |
|----------+----------------------------|
| 源语言   | 程序员写的语言             |
| 目标语言 | 编译器输出的语言，如汇编   |
| 宿主语言 | 编译器本身用什么语言写     |
| 编译器   | 一次性翻译整个程序或模块   |
| 解释器   | 边读边执行                 |
| 汇编器   | 汇编语言 -> 机器语言       |
| 连接器   | 把多个目标文件和库组合起来 |
| 装载器   | 把程序装入内存运行         |


** 编译器前端和后端

前端与源程序关系更大：

- 词法分析
- 语法分析
- 语义分析
- 中间代码生成


后端与目标机器关系更大：

- 代码优化
- 目标代码生成
- 寄存器分配
- 指令选择


有时中间代码也被看作前端和后端之间的桥梁。

** 编译阶段常考输入输出

| 阶段         | 输入      | 输出               |
|--------------+-----------+--------------------|
| 词法分析     | 字符流    | token序列          |
| 语法分析     | token序列 | 语法树/分析树      |
| 语义分析     | 语法树    | 带类型和属性的信息 |
| 中间代码生成 | 语义信息  | 三地址码           |
| 代码优化     | 中间代码  | 优化后的中间代码   |
| 代码生成     | 中间代码  | 目标代码           |


- 词法错误：非法字符、非法数字格式
- 语法错误：括号不匹配、缺少分号
- 语义错误：变量未声明、类型不匹配

* 第2章：语言及其文法

这一章要掌握四件事情：符号串、文法定义、推导与规约、二义性

** 基本概念

字母表 \( \sigma \) : 符号的有限集合

比如:

#+BEGIN_EXAMPLE
Σ = {a, b}
#+END_EXAMPLE

串：由符号组成的有限序列

#+BEGIN_EXAMPLE
a, b, ab, abb, ε
#+END_EXAMPLE

ε 是空串，长度为0。

闭包：

#+BEGIN_EXAMPLE
Σ* = Σ 上所有有限长度串的集合，包括 ε
Σ+ = Σ* 去掉 ε
#+END_EXAMPLE

比如，如果 Σ = {a, b} ，那么:

#+BEGIN_EXAMPLE
Σ* = {ε, a, b, aa, ab, ba, bb, aaa, ...}
Σ+ = {a, b, aa, ab, ba, bb, aaa, ...}
#+END_EXAMPLE

而语言 L 是 Σ* 的一个子集。

比如， \( L=\{a^nb^n | n \geq 0\} \)；表示:

#+BEGIN_EXAMPLE
ε, ab, aabb, aaabbb, ...
#+END_EXAMPLE

这个语言后面很重要。因为它不能用正规式表达，但是可以用上下文无关文法表达。

-----

** 文法的四元组

文法 G 定义为:

\[
G = (V_N, V_T, P, S)
\]

含义：

| 符号 | 含义         |
|------+--------------|
| V_N  | 非终结符集合 |
| V_T  | 终结符集合   |
| P    | 产生式集合   |
| S    | 开始符号     |


比如一个例子：

\begin{aligned}
G:\\
S \rightarrow aSb\\
S \rightarrow ε
\end{aligned}

这里:

\begin{aligned}
V_N &= \{S\}\\
V_T &= \{a,b\}\\
P &= \{S \rightarrow aSb, S \rightarrow ε\}\\
S &= S\\
\end{aligned}

 它生成的语言是： \( L(G) = \{a^nb^n | n \geq 0\} \) ，因为 \( S => aSb => aaSbb => aabb \) 。

* 词法分析

** 词法分析器在做的

#+begin_src c
  while (value != 100) {
    num++;
   }
#+end_src

经过词法分析，会得到:

#+begin_example
<WHILE, ->
<(, ->
<ID, value>
<!=, ->
<CONST, 100>
<), ->
<{, ->
<ID, num>
<++, ->
<;, ->
<}, ->
#+end_example

符号设计方法如下:

| 单词类别   | 例子                | 常见token设计 | 属性值                 |
|------------+---------------------+---------------+------------------------|
| 关键字     | ~if~ ~while~ ~else~ | 一词一符      | 通常无                 |
| 数据类型   | ~int~ ~float~       | ~TYPE~        | 类型字符串             |
| 标识符     | ~count~ ~result~    | ~ID~          | 名字字符串或符号表入口 |
| 常量       | ~17~ ~3.14~         | ~INT~ ~FLOAT~ | 数值                   |
| 算术运算符 | ~+~ ~-~ ~++~        | 一词一符      | 通常无                 |
| 关系运算符 | ~>~ ~<~ ~!=~        | ~RELOP~       | 运算符类型             |
| 界限符     | ~;~ ~,~ ~(~         | 一词一符      | 通常无                    |

三个概念：

| 概念            | 含义                       | 例子                   |
|-----------------+----------------------------+------------------------|
| 词素 lexeme     | 源程序中实际出现的字符序列 | ~count~                |
| token种别       | 词素所属类别               | ~ID~                   |
| 属性值attribute | token所携带的附加信息      | ~"count"~ 或符号表位置 |


*** 应用题1：写出token序列

#+begin_src c
  if count >= 7 then result := 3.14;
#+end_src

可以写成:

#+begin_example
<IF, ->
<ID, count>
<RELOP, >=>
<INT, 7>
<THEN, ->
<ID, result>
<ASSIGN, ->
<FLOAT, 3.14>
<SEMIC, ->
#+end_example

如果题目没有指定编码规则，可以自定义合理的名字，但是要保持一致。

** 正则表达式: 用有限规则描述无限多个单词

正则表达式 Regular Expression ，简称 RE,用于描述正则语言。

*** 三个基本运算

假设 ~r~ 和 ~s~ 都是正则表达式:

| 写法      | 含义       | 例子                                |
|-----------+------------+-------------------------------------|
| r \vert s | 或、并集   | a \vert b 表示 {a, b}               |
| rs        | 连接       | ab 表示字符串 "ab"                  |
| r*        | Kleene闭包 | a* 表示 {ε, a, aa, aaa, aaaa, ....} |


优先级从高到低排列: * -> 连接 -> |

因此 ~ab*|c~ 等价于 ~a(b*) | c~

-----

*** 例子

例1：由 ~a~ 和  ~b~ 组成的任意字符串

~(a|b)*~

例2：以 ~aab~ 结尾的字符串

~(a|b)*aab~

例3：至少包括一个 ~a~

~(a|b)*a(a|b)*~

例4：恰好包括一个 ~a~

~b*ab*~

例5：包含偶数个 ~a~

~b*(ab*ab*)*~

** 程序设计语言中常见单词的正则定义

*** 标识符

#+begin_example
digit -> 0|1|2|...|9
letter_ -> A|B|...|Z|a|b|...|z|_
id -> letter_(letter_|digit)*
#+end_example

简写为:

#+begin_example
id = [A-Za-z_][A-Za-z0-9_]*
#+end_example

*** 十进制无符号整数

如果允许数字0,同时禁止以多位数字0开头：

~0|(1|2|...|9)(0|1|...|9)*~

简写为:

~0|[1-9][0-9]*~

*** 十六进制无符号整数

~0x[0-9a-fA-F]+~

~+~ 表示至少出现一次。

*** 无符号数：整数、浮点数、科学计数法

#+begin_example
digit -> 0|1|2|...|9
digits -> digit digit*
optionalFraction -> .digits | ε
optionalExponent -> E(+|-|ε)digits | ε
number -> digits optionalFraction optionalExponent
#+end_example

** 有限自动机：真正负责识别单词的机器

有限自动机可以理解为一种极简的状态机：

#+begin_example
当前状态 + 当前字符 -> 下一状态
#+end_example

扫描器从左到右读取字符，不需要记住完整历史，只需要记住当前状态。

*** DFA 的五元组

确定有限自动机 DFA 可以写成：

#+begin_example
M = (s, Σ, move, s0, F)
#+end_example

| 符号   | 含义         |
|--------+--------------|
| ~S~    | 状态集合     |
| ~Σ~    | 输入字母表   |
| ~move~ | 转换函数     |
| ~s0~   | 初始状态     |
| ~F~    | 接受状态集合 |


DFA 中，每个状态+每个输入字符 最多对应一个后继状态。和NFA的主要区别是，NFA允许空边，但是DFA不允许。

** 从正则表达式构造 ε-NFA：Thompson 算法

常见流程: RE -> ε-NFA -> DFA

*** 基本符号

正则表达式 ~a~ 对应 ~(start) --a--> (end)~

正则表达式 ~ε~ 对应 ~(start) --ε--> (end)~

-----

*** 连接

比如，对于两个正则表达式 ~r1~ ~r2~

构造:

\( \texttt{(start of r1)} ... \texttt{(end of r1)} \xrightarrow{ε} \texttt{(start of r2)} ... \texttt{(end of r2)} \)

比如: ~ab~ ，对应 \( 0 \xrightarrow{a} 1 \xrightarrow{ε} 2 \xrightarrow{b} 3 \)

-----

*** 或运算

对于 ~r1|r2~ 可以添加一个新起点和一个新终点。

-----

*** Kleene 闭包

对于 ~r*~ ，构造逻辑是：

1. 新起点可以直接到新终点
2. 新起点也可以进入 N(r)
3. N(r) 的终点可以回到 N(r) 的起点
4. N(r) 的终点也可以离开


上面的逻辑允许 ~r~ 出现0次、1次、2次...

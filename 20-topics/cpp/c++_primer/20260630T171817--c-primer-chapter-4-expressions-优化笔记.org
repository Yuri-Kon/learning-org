* Chapter 4 主线：表达式不是“算式”，而是“求值规则”

第四章应压缩成一条主线：

#+begin_quote
表达式 = 操作数 + 运算符；真正重要的是：类型如何转换、值类别是什么、运算符如何分组、副作用何时发生。
#+end_quote

以后遇到任何复杂表达式，按四个问题复盘：

1. 这个表达式的结果类型是什么？
2. 它的结果是 lvalue / xvalue / prvalue 中哪一种？
3. 哪些地方发生了隐式转换？尤其是 signed/unsigned、窄化、数组到指针。
4. 哪些子表达式有副作用？这些副作用是否被明确排序？

C++ Primer 第 4 章以 C++11 的表达式模型为底本，核心是运算符、优先级、结合性、求值顺序、类型转换和显式 cast。本笔记不复述完整解释，只保留可用于写代码、避坑和复盘的索引。

* 1. Fundamentals：表达式的四个底层问题

** 1.1 运算符维度

- unary operator：一元运算符，例如 ~&x~ 、 ~*p~ 、 ~!cond~ 、 ~++i~ 。
- binary operator：二元运算符，例如 ~a + b~、~a == b~。
- ternary operator：条件运算符 ~cond ? a : b~。
- function call：函数调用运算符，操作数数量不限。

同一个符号可能有多个含义，例如：

#+begin_src cpp
  *p;      // unary *，解引用
  a * b;   // binary *，乘法
  &x;      // unary &，取地址
  a & b;   // binary &，按位与
#+end_src

重载运算符可以改变“对类类型的语义”，但不能改变操作数个数、优先级和结合性。

** 1.2 值类别：C++11 以后不只是 lvalue/rvalue

Primer 这一章主要使用 lvalue / rvalue 的粗略二分：

- lvalue：关心对象身份，可以定位到某个对象或函数。
- rvalue：关心表达式的值，通常不能作为需要可修改对象位置的地方。

现代 C++ 标准把表达式分成三个 fundamental categories： ~lvalue~ 、 ~xvalue~ 、 ~prvalue~ 。 ~rvalue~ 是 ~xvalue~ 或 ~prvalue~ ， ~glvalue~ 是 ~lvalue~ 或 ~xvalue~ 。初学阶段可以先用以下工作模型：

- 能稳定指向某个已有对象身份的，通常是 lvalue。
- 临时值、纯计算结果，通常是 prvalue。
- 即将被移动、资源可被复用的对象表达式，通常是 xvalue，例如 ~std::move(x)~ 的结果。

常见运算符结果：

- 赋值表达式：要求左侧是可修改 lvalue；结果仍是左侧对象，是 lvalue。
- 取地址 ~&x~ ：要求操作数通常是 lvalue；结果是指针 prvalue。
- 解引用 ~*p~ ：结果是 lvalue。
- 下标 ~v[i]~ ：对 ~vector~ 、 ~string~ 、内置数组通常结果是 lvalue。
- 前缀 ~++i~ ：结果是修改后的对象，是 lvalue。
- 后缀 ~i++~ ：结果是旧值的副本，是 prvalue。

** 1.3 decltype 的复盘规则

~decltype~ 问的是“表达式的精确类型和值类别”。

#+begin_src cpp
  int v{};
  int* p = &v;

  decltype(*p) r = v;   // int&，因为 *p 是 lvalue
  decltype(&p) pp = &p; // int**，因为 &p 的结果是指针值
#+end_src


现代补充：

#+begin_src cpp
  int x = 0;
  decltype(x) a = x;    // int，名字表达式按声明类型
  decltype((x)) b = x;  // int&，(x) 是更一般的 lvalue 表达式
#+end_src

这以后会影响 ~decltype(auto)~ 的函数返回值推导。

* 2. Precedence / Associativity / Evaluation Order

** 2.1 优先级和结合性只决定“怎么分组”

- precedence：不同优先级的运算符如何绑定操作数。
- associativity：同优先级运算符如何分组。
- 它们不等于求值顺序。

例如：

#+begin_src cpp
  3 + 4 * 5;      // 3 + (4 * 5)
  20 - 15 - 3;    // (20 - 15) - 3
  *ia + 4;        // (*ia) + 4
  *(ia + 4);      // 访问 ia[4]
#+end_src

笔记建议：不要背完整优先级表，只背高频陷阱：

- 后缀 ~++~ 高于解引用： ~*it++~ 等价于 ~*(it++)~ 。
- 点运算符高于解引用： ~(*p).size()~ 或 ~p->size()~ 。
- 位移 ~<<~ / ~>>~ 低于算术，高于关系。
- 赋值、条件运算符优先级很低。
- 关系运算符不能数学式连写： ~i < j < k~ 不是你想要的。

** 2.2 求值顺序：副作用的真正风险来源

不要把“左结合”理解成“从左到右求值”。

#+begin_src cpp
  f() + g() * h() + j();
#+end_src

这里：

- 优先级保证 ~g() * h()~ 被分组。
- 结合性保证加法如何分组。
- 但这些函数的调用顺序通常不由优先级/结合性决定。

通用安全规则：

#+begin_quote
如果一个表达式中某个对象被修改，就不要在同一个表达式的其他不受排序保证的位置再次读取或修改它。
#+end_quote

例外是子表达式内部存在天然依赖：

#+begin_src cpp
  *++it; // 先 ++it，再解引用；这是常见且清晰的 idiom
#+end_src

现代标准补充：C++17 起，若使用运算符写法调用重载运算符，其实参求值会遵循对应内置运算符的排序规则；当前标准草案中 shift expression 明确左操作数先于右操作数求值。因此，Primer 中 ~cout << i << " " << ++i~ 这个 C++11/14 时代的典型未定义示例，在 C++17+ 的规则下需要重新判断。不过作为代码风格，仍然不要依赖这种混写副作用的表达式。

* 3. 算术运算符：重点是溢出、除法、提升

** 3.1 小整数提升

大多数算术表达式中，~bool~、~char~、~short~ 等小整数类型会先 integral promotion，通常提升为 ~int~。

#+begin_src cpp
  bool b = true;
  bool b2 = -b; // b -> 1, -1 再转回 bool，结果仍是 true
#+end_src

这说明：不要把 ~bool~ 当作数字参与计算。

** 3.2 整数除法和取余

#+begin_src cpp
  21 / 6;   // 3
  21 % 6;   // 3
  -21 / 8;  // -2，向 0 截断
  -21 % 8;  // -5，余数符号跟左操作数一致
#+end_src

复盘规则：如果 ~m~ 和 ~n~ 是整数且 ~n != 0~，则：

#+begin_src cpp
  (m / n) * n + m % n == m
#+end_src

** 3.3 溢出

- signed integer overflow：未定义行为。
- unsigned integer overflow：按模 2^N 回绕，这是定义良好的，但仍然可能不是业务想要的结果。

实践建议：

- 计数、大小优先用容器提供的 ~size_type~ 或 ~auto~。
- 需要固定宽度时用 ~std::int32_t~ / ~std::uint32_t~ 等。
- 编译时打开 ~-Wall -Wextra -Wconversion -Wsign-conversion~。
- 练习阶段可打开 UBSan：~-fsanitize=undefined~。

* 4. Logical and Relational Operators

** 4.1 短路求值是安全访问的重要工具

#+begin_src cpp
  if (!s.empty() && s[0] == 'x') { }
  if (p != nullptr && *p > 0) { }
#+end_src

~&&~ 左侧为 false 时不求值右侧；~||~ 左侧为 true 时不求值右侧。

** 4.2 不要链式比较

错误写法：

#+begin_src cpp
  if (i < j < k) { }
#+end_src

实际分组：

#+begin_src cpp
  if ((i < j) < k) { }
#+end_src

正确写法：

#+begin_src cpp
  if (i < j && j < k) { }
#+end_src

你原笔记易错点里写成了 ~if (i < k && k < j)~，这与“i < j < k”的语义不一致，应改为 ~i < j && j < k~。

** 4.3 不要把非 bool 和 true/false 比较

#+begin_src cpp
  if (val)        { } // val 非 0
  if (!val)       { } // val 为 0
  if (val == true){ } // 如果 val 不是 bool，通常等价于 val == 1
#+end_src

因此：

- 对 ~bool~ 对象，可以写 ~if (flag)~ 或 ~if (!flag)~。
- 对整数，直接写业务条件：~count != 0~、~index >= 0~。
- 对指针，用 ~p != nullptr~ 更清楚。

* 5. Assignment Operators

** 5.1 左侧必须是 modifiable lvalue

非法：

#+begin_src cpp
  1024 = k;
  i + j = k;
  ci = k; // ci 是 const
#+end_src

赋值表达式的结果是左操作数本身，因此：

#+begin_src cpp
  int a, b;
  a = b = 0; // 右结合：a = (b = 0)
#+end_src

** 5.2 条件中的赋值必须加括号

#+begin_src cpp
  while ((i = get_value()) != 42) {
      // ...
  }
#+end_src

如果写成：

#+begin_src cpp
  while (i = get_value() != 42) { }
#+end_src

则先计算 ~get_value() != 42~，再把 bool 结果赋给 ~i~。

#+begin_src cpp
  if (i = j)  { } // 赋值后测试 i，通常是 bug
  if (i == j) { } // 比较
#+end_src

** 5.3 复合赋值

#+begin_src cpp
  a += b; // 近似 a = a + b，但 a 只求值一次
#+end_src

当左侧表达式有副作用或计算成本时， ~a op= b~ 和 ~a = a op b~ 的差别可能重要。

* 6. Increment and Decrement Operators

** 6.1 默认使用前缀形式

#+begin_src cpp
  ++i; // 修改后返回对象自身，lvalue
  i++; // 修改对象，但返回旧值副本，prvalue
#+end_src

实践建议：

- 不需要旧值时，写 ~++i~ / ~++it~ 。
- 需要“先用旧值再前进”时，写后缀，例如 ~*it++~ 。

** 6.2 理解 *it++

#+begin_src cpp
  std::cout << *it++ << '\n';
#+end_src

等价于：

#+begin_src cpp
  std::cout << *it << '\n';
  ++it;
#+end_src

但这依赖后缀 ~++~ 返回旧迭代器副本。

** 6.3 不要在赋值左右两侧混用修改同一迭代器

#+begin_src cpp
  *beg = std::toupper(*beg++); // 不要这样写
#+end_src

写成两句更安全：

#+begin_src cpp
  *beg = std::toupper(static_cast<unsigned char>(*beg));
  ++beg;
#+end_src

补充： ~std::toupper~ 传入负的 ~char~ 值也可能出问题，实践中常先转为 ~unsigned char~ 。

* 7. Member Access Operators

#+begin_src cpp
  std::string s = "abc";
  std::string* p = &s;

  p->size();      // 等价于 (*p).size()
  (*p).size();    // 正确
  *p.size();      // 错误，等价于 *(p.size())
#+end_src

规则：

- 对对象用 ~.~ 。
- 对指针用 ~->~ 。
- 需要先解引用再访问成员时，加括号。

* 8. Conditional Operator

#+begin_src cpp
  auto result = cond ? expr1 : expr2;
#+end_src

特点：

- 只有一个分支会被求值。
- 条件运算符右结合。
- 优先级很低，嵌入输出表达式时必须加括号。

#+begin_src cpp
  std::cout << ((grade < 60) ? "fail" : "pass"); // 正确
  std::cout << (grade < 60) ? "fail" : "pass";   // 打印 0/1，不是想要的
#+end_src

实践建议：

- 简单二选一：可以用 ~?:~ 。
- 三层以上分类：用 ~if/else~ 或查表。
- 两个分支有副作用：优先用 ~if/else~ 。

* 9. Bitwise Operators

** 9.1 位运算符表

- ~~~ ：按位取反。
- ~<<~ / ~>>~ ：左移 / 右移。
- ~&~ ：按位与，两个 bit 都为 1 时结果为 1。
- ~|~ ：按位或，至少一个 bit 为 1 时结果为 1。
- ~^~ ：按位异或，两个 bit 不同为 1，相同为 0。

** 9.2 位掩码基本操作

#+begin_src cpp
  unsigned long quiz = 0;

  quiz |=  (1UL << 27);  // set bit 27
  quiz &= ~(1UL << 27);  // clear bit 27
  bool status = quiz & (1UL << 27); // test bit 27
#+end_src

实践建议：

- 位掩码优先用 unsigned 类型。
- 更现代的代码可以用 ~std::uint32_t~ / ~std::uint64_t~ 表达固定宽度。
- 如果只是表达一组布尔位，可以先学会 ~std::bitset<N>~。
- C++17 起可考虑 ~std::byte~ 表达“原始字节”，避免把字节当整数误算。

** 9.3 移位陷阱

- 右操作数不能为负。
- 右操作数必须小于左操作数提升后的位宽。
- 例如 ~1 << 31~ 中，~1~ 是 ~int~，这在旧标准和具体平台上容易踩坑；写掩码时优先写 ~1u~、~1UL~ 或固定宽度类型。

现代补充：当前标准草案对 signed right shift 已描述为算术右移并进行符号扩展，但跨项目、跨标准版本和可读性角度，位掩码仍建议使用 unsigned。

* 10. sizeof Operator

#+begin_src cpp
  sizeof(type)
  sizeof expr
#+end_src

特点：

- 结果类型是 ~std::size_t~ 。
- 结果是常量表达式。
- 操作数通常不被求值。

#+begin_src cpp
  int* p = nullptr;
  sizeof *p; // 合法：不真正解引用 p
#+end_src

数组和指针要特别区分：

#+begin_src cpp
  int arr[10];
  int* p = arr;

  sizeof arr; // 整个数组大小
  sizeof p;   // 指针本身大小
#+end_src

* 11. Comma Operator

逗号运算符保证左表达式先于右表达式求值，结果是右表达式的结果。

常见场景是 ~for~ 的第三部分：

#+begin_src cpp
  for (std::vector<int>::size_type ix = 0, cnt = v.size();
       ix != v.size();
       ++ix, --cnt) {
      v[ix] = cnt;
  }
#+end_src

实践建议：

- ~for~ 循环头里可以少量使用逗号。
- 普通业务逻辑中尽量不用逗号运算符，容易被误读为分隔符。

* 12. Type Conversions

** 12.1 隐式转换发生的地方

常见场景：

- 小整数类型提升。
- 条件中转换到 ~bool~。
- 初始化时，初始化器转换到目标类型。
- 赋值时，右侧转换到左侧类型。
- 算术/关系运算中转换到 common type。
- 函数调用中发生参数转换。
- 数组名在多数表达式中转换为指向首元素的指针。

** 12.2 算术转换：重点防 signed/unsigned

#+begin_src cpp
  int i = -1;
  unsigned u = 1;

  if (i < u) { } // 可能不是你直觉里的 true
#+end_src

原因：如果 ~int~ 和 ~unsigned int~ 运算， ~int~ 通常转换为 ~unsigned int~ 。

实践建议：

- 不要混用 signed 和 unsigned 做大小比较。
- 容器下标如果要倒序，注意 ~size_type~ 是无符号类型。
- C++20 可用 ~std::ssize(container)~ 得到有符号长度。
- C++20 可用 ~std::cmp_less~、~std::cmp_greater~ 处理有符号/无符号比较。

** 12.3 数组到指针转换的例外

以下场景数组不会退化成指针：

- ~sizeof arr~
- ~decltype(arr)~
- ~&arr~
- 绑定到数组引用

#+begin_src cpp
  int arr[10];
  auto p = arr;          // int*
  auto& ref = arr;       // int (&)[10]
  decltype(arr) another; // int[10]，但这里未初始化会有问题
#+end_src

** 12.4 指针转换

现代 C++：优先使用 ~nullptr~，不要用 ~0~ 或 ~NULL~ 表达空指针。

#+begin_src cpp
  int* p = nullptr;
  if (p != nullptr) { }
#+end_src

原因：~nullptr~ 有专门类型 ~std::nullptr_t~，可以转换为任意指针类型，但不是整数。

** 12.5 显式转换：named casts

C++ 风格 cast：

#+begin_src cpp
  cast_name<target_type>(expression)
#+end_src

四种 named cast：

- ~static_cast~：定义良好的普通转换，例如数值转换、~void*~ 转回原指针类型。
- ~const_cast~ ：只改变 low-level const/volatile，不能改变底层类型。
- ~reinterpret_cast~ ：重新解释位模式，非常危险，除非你明确在做底层接口/序列化/ABI 相关工作。
- ~dynamic_cast~ ：运行期多态类型转换，后面学继承和虚函数时再深入。

实践原则：

- 需要表达“我知道这里会损失精度”时，用 ~static_cast~ 。
- 不要用 C 风格 cast： ~(T)x~ ，因为它可能混合多种转换，审查困难。
- ~const_cast~ 只能用于你确定底层对象本来不是 const 的情况；对真正的 const 对象写入是 UB。
- ~reinterpret_cast~ 出现时应该触发代码审查警报。

* 14. 第四章复盘清单

写完涉及表达式的代码后，快速问自己：

- 是否在一个表达式里同时修改并读取同一个对象？
- 是否混用了 signed 和 unsigned？
- 是否依赖了隐式窄化转换？
- 是否把 ~val == true~ 写在非 bool 对象上？
- 是否使用了后缀 ~++~ 但并不需要旧值？
- 是否把 ~i < j < k~ 当数学式写了？
- 是否对指针成员访问忘记 ~->~ 或 ~(*p).member~？
- 位移右操作数是否可能越界或为负？
- 是否能用括号提高可读性？
- 是否使用了 C 风格 cast？能否换成 named cast？

* 15. 练习：用于真正内化

** A. 值类别与 decltype

判断下面每个表达式的值类别，以及 ~decltype(expr)~ 的结果：

#+begin_src cpp
  int i = 0;
  int* p = &i;
  int& r = i;

  i;
  (i);
  r;
  ,*p;
  &p;
  ++i;
  i++;
  i + 1;
#+end_src

目标：理解“名字的声明类型”和“表达式值类别”不是一回事。

*** A. 解答
| 表达式  | 表达式类型 | 值类别  | ~decltype(...)~ |
|---------+-------------+---------+-----------------|
| ~i~     | ~int~       | lvalue  | ~int~           |
| ~(i)~   | ~int~       | lvalue  | ~int&~          |
| ~r~     | ~int~       | lvalue  | ~int&~          |
| ~*p~    | ~int~       | lvalue  | ~int&~          |
| ~&p~    | ~int**~     | prvalue | ~int**~         |
| ~++i~   | ~int~       | lvalue  | ~int&~          |
| ~i++~   | ~int~       | lvalue  | ~int~           |
| ~i + 1~ | ~int~       | prvalue | ~int~           |


** B. 求值顺序与 UB 审查

判断下面哪些应该重写，并给出更清楚的写法：

#+begin_src cpp
  int i = 0;
  int a = i++ + i;
  int b = ++i + 1;
  v[i] = i++;
  std::cout << i << ' ' << ++i << '\n';
#+end_src

*** B. 解答

应该重写:
- ~int a = i++ + i;~ : ~int a = i++; a += i~
- ~v[i] = i++~ : ~i++; v[i] = i;~
- ~std::cout << i << ' ' << ++i << '\n';~ : 可以改写

要求：分别按 C++11/14 和 C++17+ 思路复盘，不要只看某个编译器输出。

** C. signed/unsigned 陷阱

写一个程序打印下面表达式的结果，并解释原因：

#+begin_src cpp
  int i = -1;
  unsigned u = 1;
  std::cout << (i < u) << '\n';
#+end_src

然后改写成更安全的 C++20 版本：

#+begin_src cpp
  #include <utility>
  std::cmp_less(i, u);
#+end_src

*** C. 解答:
结果是:
#+begin_quote
0
#+end_quote
也就是说这里的 ~i < u~ 的结果是 ~false~ 。因为在比较过程中， ~int~ 通常会被转化为 ~unsigned int~ . 又因为 ~i~ 是 -1, 因此会被转化为很大的值。

** D. 位运算小工具

实现三个函数：

#+begin_src cpp
  bool test_bit(std::uint32_t mask, int pos);
  void set_bit(std::uint32_t& mask, int pos);
  void clear_bit(std::uint32_t& mask, int pos);
#+end_src

要求：

- 检查 ~pos~ 范围。
- 不允许右移/左移越界。
- 使用 ~1u~ 或 ~std::uint32_t{1}~。


*** D. 解答
#+begin_src cpp
  #include <cstdint>
  #include <iostream>

  /*
   ,* 测试 mask 的 第 pos 位是不是1
   ,*
   ,* pos 从 0 开始
   ,*/
  bool test_bit(std::uint32_t mask, int pos) {
    return mask &(std::uint32_t{1} << pos);
  }

  /*
   ,* 将 mask 的 pos 位变为1
   ,*/
  void set_bit(std::uint32_t &mask, int pos) {
    mask |= (std::uint32_t{1} << pos);
  }

  /*
   ,* 将 mask 的第 pos 位清零
   ,*/
  void clear_bit(std::uint32_t &mask, int pos) {
    mask &= ~(std::uint32_t{1} << pos);
  }
  int main() {
    std::uint32_t mask = 0b00000001;

    std::cout << test_bit(mask, 0) << std::endl;

    set_bit(mask, 2);
    std::cout << mask << std::endl;

    clear_bit(mask, 0);
    std::cout << mask << std::endl;
    return 0;
  }
#+end_src

* 16. 最终索引

1. 表达式分析四问：类型、值类别、转换、副作用排序。
2. 现代值类别：lvalue / xvalue / prvalue；rvalue = xvalue 或 prvalue。
3. 优先级/结合性只决定分组，不保证求值顺序。
4. 有副作用的表达式要拆开写，除非排序关系非常明确。
5. ~&&~ 、 ~||~ 、 ~?:~ 、 ~,~ 有明确求值规则；C++17+ 又补充了一些运算符排序。
6. signed overflow 是 UB；unsigned 回绕是定义良好的但不一定符合业务。
7. 整数除法向 0 截断；取余满足 ~(m/n)*n + m%n == m~ 。
8. 不要写 ~i < j < k~，写 ~i < j && j < k~ 。
9. 不要对非 bool 写 ~val == true~ 。
10. 赋值左侧必须是 modifiable lvalue；赋值表达式结果是左侧 lvalue。
11. 条件里的赋值必须加括号，并确认不是误写 ~==~ 。
12. 默认用前缀 ~++it~ ；只有需要旧值才用 ~it++~ 。
13. ~*it++~ 等价于 ~*(it++)~ ，是“使用当前元素并前进”的 idiom。
14. 成员访问：对象用 ~.~ ，指针用 ~->~ ，解引用后访问写 ~(*p).m~ 。
15. 条件运算符低优先级，输出时要整体加括号。
16. 位运算优先用 unsigned；移位位数不能为负或越界。
17. ~sizeof~ 不求值操作数；区分数组大小和指针大小。
18. 逗号运算符保证左到右，但日常逻辑少用。
19. 小整数会提升；混合算术转换会找 common type。
20. 不用 C 风格 cast；优先 named cast，尤其警惕 ~reinterpret_cast~。

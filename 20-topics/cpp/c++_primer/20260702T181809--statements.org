* 异常处理
本章除异常处理之外均为基础知识，故不再赘述。

异常处理用于处理运行时异常情况：某段代码发现问题，但它自己无法解决、也不应该决定如何恢复，于是通过 ~throw~ 将问题抛出去；另一段更高层、更懂上下文的代码通过 ~try/catch~ 解决。异常处理分为三部分: ~throw~ 表达式、 ~try~ 块、异常类

典型结构是:
#+begin_src cpp
  #include <iostream>
  int divide(int lhs, int rhs) {
    if (rhs == 0) {
      throw std::runtime_error("division by zero");
    }
    return lhs / rhs;
  }

  int main() {
    int a = 0, b = 0;
    try{
      std::cout << divide(a, b) << '\n';
    } catch (const std::runtime_error &error) {
      std::cerr << "error: " << err.what() << '\n';
    }
  }
#+end_src
* ~throw~ 发现错误的一方负责报告
 ~throw expression~ , 这个表达式的类型决定抛出的异常类型。上述例子中抛出的是 ~runtime_error~ 对象。抛出异常会终止当前正常执行路径，并把控制权交给能处理该异常类型的 ~catch~ .

 ~throw~ 不是 ~return~, ~return~ 是函数正常返回， ~throw~ 表示函数无法继续完成它承诺的工作。
* ~try~ / ~catch~: 处理错误的一方负责恢复或终止
~try~ 块会包住 “可能抛异常的普通逻辑”，后面跟着一个或多个 ~catch~ 。如果 ~try~ 中抛出的异常能匹配某个 ~catch~, 就执行对应处理代码； ~catch~ 处理完后，程序就继续执行整个 ~try~ / ~catch~ 后面的语句。 ~try~ 块内部定义的变量只在 ~try~ 块内可见，不能在 ~catch~ 中可用。

现代 C++ 通常这样写:
#+begin_src cpp
  catch (const std::runtime_error &err)
#+end_src
这里传递的是 ~const~ 左值引用，可以避免复制。即:
#+begin_quote
~throw~ by value, ~catch~ by reference
#+end_quote
* 异常处理解决什么问题
异常用于处理运行期异常情况，例如输入不合法、数据库链接丢失、文件打不开等。它适合这种情况: *发现错误的地方无法处理，也无法继续，但它又不知道应该谁来处理* 。所以异常把程序分为两部分：检测错误的一方 ~throw~, 处理错误的一方 ~try/catch~ 。

异常不是 ~if~ 的替代品，而是 “把错误从底层传播到有能力处理它的上层”。
* ~throw~: 报告无法处理的问题
~throw~ 后面跟一个表达式，表达式的类型决定抛出的异常类型：

#+begin_src cpp
  #include <stdexcept>

  if (item1.isbn() != item2.isbn()) {
    throw std::runtime_error("Data must refer to same ISBN");
  }
#+end_src
* ~try~ / ~catch~: 把正常逻辑和错误处理区分
#+begin_src cpp
  try {
    // 正常逻辑
  } catch (const std::runtime_error &e) {
    std::cerr << e.what() << '\n';
  }
#+end_src
~try~ 块本身是作用域。 ~try~ 内定义的变量不能在 ~catch~ 中访问；如果错误处理需要某个状态，就要定义在 ~try~ 外，或者把状态封进对象。
* 异常传播与栈展开
当异常被抛出时，程序会沿着调用链反向寻找匹配的 ~catch~ 。如果当前函数没有匹配处理器，当前函数退出，然后搜索调用者；继续向上，直到找到合适的 handler. 找不到 handler 时调用 ~std::terminate~, 程序终止。

这个过程伴随 stack unwinding: 控制流向上回退时，已经构造完成、尚未销毁的自动存储期对象会按构造完成的逆序调用析构函数。这个机制是 RAII 能在异常下工作的基础。

因此， C++ 异常处理和资源管理强相关。不要裸 ~new/delete~ 管理资源，要让资源放进对象里，例如 ~std::vector~, ~std::string~, 智能指针、文件流对象等。异常发生时，对象析构会自动释放资源。
* 异常安全
异常会中断正常控制流，可能导致部分操作已经完成、部分操作还没完成；如果处理不好，会留下无效对象、资源泄露或不一致状态。能在异常下仍正确处理和保持状态的代码称为 exception safe.

三层目标:

| 保证     | 含义                                       |
|----------+--------------------------------------------|
| 基本保证 | 不泄露内存，对象仍保持有效状态           |
| 强保证   | 操作失败时，状态回到调用前，好像没发生过 |
| 不抛保证 | 函数承诺不抛异常                          |

现代C++中， ~noexcept~ 是接口的一部分。如果函数确定不会抛异常，应声明 ~noexcept~. 这不仅表达接口承诺，也可能让编译器生成功耗的代码。尤其移动操作和 ~swap~ 是否 ~noexcept~ ，会影响标准库容器在扩容等操作中能否安全地移动元素。

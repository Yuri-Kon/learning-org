* Generic Algorithms (泛型算法)

标准库算法是一套建立在 iterator / range 之上的通用序列操作语言。容器本身只提供少量基础操作，而大量查找、统计、替换、复制、排序、去重等工作交给泛型算法去完成。这些算法通常不直接操作容器，而是通过一对迭代器表示的范围工作。
* 泛型算法总纲
算法不是容器成员，而是 “范围上的函数”。

传统写法通常是:
#+begin_src cpp
  std::vector<int> v{1, 4, 2, 9, 4};
  auto it = std::find(v.begin(), v.end(), 4);
#+end_src
~std:find~ 不知道 ~v~ 是 ~vector~ 、 ~list~ 、数组还是某个自定义容器，它只知道:
#+begin_src cpp
  [first, last)
#+end_src
也就是一个左闭右开范围 *(half-open range)* .

这种设计有三个重要后果:
1. 算法和容器解耦。只要某个对象能提供合适的迭代器，算法就能工作，内置数组也可以。
2. 算法依赖的是 *迭代器能力 (iterator capability)*, 不是容器的名字。比如 ~std::find~ 只需要能逐个读取元素，所以 ~vector~, ~list~, ~forward_list~ 都可以；而 ~std::sort~ 需要随机访问迭代器，所以不能直接用于 ~std::list~ 。
3. 泛型算法本身一般不会改变容器大小。它可以修改元素值、移动元素位置，但不会直接调用 ~push_back~, ~erase~, ~insert~ 等这类容器操作。算法以迭代器为基础，不能直接添加或删除容器元素；即是用了 ~back_inserter~, 真正扩容的是插入迭代器调用容器操作，而不是算法本身。

算法操作的是序列视图，不是容器对象本身
#+end_quote
* 算法的分类
** 只读算法 (read-only algorithms)
这些算法读取元素，不修改元素。

常见有:
#+begin_src cpp
  std::find;
  std::find_if;
  std::count;
  std::count_if;
  std::accumulate;
  std::equal;
  std::all_of;
  std::any_of;
  std::none_of;
#+end_src
例子:
#+begin_src cpp
  std::vector<int> v{1, 2, 3, 4, 5, 6, 7};
  auto n = std::count(v.cbegin(), v.cend(), 2);
#+end_src
对于只读算法，优先使用:
#+begin_src cpp
  v.cbegin(), v.cend();
#+end_src
~std::accmulate~ 在 ~<numberic>~ 里，而不是 ~<algorithm>~ 里。
#+begin_src cpp
  #include <numeric>
  std::vector<int> v{1, 2, 3};
  int sum = std::accmulate(v.cbegin(), v.cend(), 0);
#+end_src
这里有一个经典的陷阱: *第三个参数决定累加结果类型*

#+begin_src cpp
  std::vector<double> v{1.5, 2.5};

  auto wrong = std::accumulate(v.cbegin(), v.cend(), 0); // int 累加
  auto right = std::accumulate(v.cbegin(), v.cend(), 0.0); // double 累加
#+end_src
同理，拼接字符串时需要写:
#+begin_src cpp
  std::vector<std::string> words{"a", "b", "c"};
  auto s = std::accumulate(words.cbegin(), words.cend(), std::string{});
#+end_src
** 写入算法 (writing algorithms)
这些算法会写入某个范围或输出位置。

常见有:
#+begin_src cpp
  std::fill;
  std::fill_n;
  std::copy;
  std::copy_if;
  std::replace;
  std::replace_copy;
  std::transform;
#+end_src
直接写已有范围:
#+begin_src cpp
  std::vector<int> v(10);
  std::fill(v.begin(), v.end(), 0);'
#+end_src
写到输出迭代器:
#+begin_src cpp
  std::vector<int> src{1, 2, 3};
  std::vector<int> dst;

  std::copy(src.cbegin(), src.cend(), std::back_inserter(dst));
#+end_src
注意这里危险写法是: ~std::copy(src.cbegin(), src.cend(), dst.begin());~ , 因为此时的 ~dst~ 中没有元素。

#+begin_quote
写入算法不会帮你自动扩容；除非显示使用插入迭代器 (insert iterator)
#+end_quote
** 重排算法 (reordering algorithms)
这些算法改变元素顺序:
#+begin_src cpp
  std::sort
  std::stable_sort
  std::reverse
  std::rotate
  std::partition
  std::stable_partition
  std::unique
  std::shuffle
#+end_src
经典的去重流程是:
#+begin_src cpp
  std::vector<std::string> words{
    "the", "quick", "red", "fox", "red", "the"
  };
  std::sort(words.begin(), words.end());
  auto new_end = std::unique(words.begin(), words.end());
  words.erase(new_end, words.end());
#+end_src
注意: ~std::unique()~ 并不会真正删除元素。它只是把相邻重复元素 “压缩” 到前面，并返回新的逻辑终点。真正删除元素的是容器成员函数:
#+begin_src cpp
  words.erase(new_end, words.end());
#+end_src
因此如果单独写 ~std::unique()~ 通常是错的，因为容器大小没有变化。类似的， ~std::remove~ / ~std::remove_if~ 也不会真的删除元素。传统写法叫: *erase-remove idiom*:
#+begin_src cpp
  v.erase(
  	std::remove(v.begin(), v.end(), value),
  	v.end
  	);
#+end_src
C++20 之后，对于标准容器，很多场景可以直接用:
#+begin_src cpp
  std::erase(v, value);
  std::erase_if(v, pred);
#+end_src
这两个函数是C++20的统一容器删除接口；以 ~vector~ 为例， ~erase_if~ 相当于先 ~remove_if~ 在调用容器的 ~erase~ 。
* 自定义操作: predicate, lambda, comparator
算法默认通常依赖元素类型的 ~==~ 或 ~<~ .

例如:
#+begin_src cpp
  std::sort(words.begin(), words.end());
#+end_src
默认会使用 ~operator<~ .如果要按照字符串长度排序，则需要提供比较函数。更现代的写法是使用 lambda expression:
#+begin_src cpp
  std::stable_sort(words.begin(), words.end(), [](const std::string &a, const std::string &b) {return a.size() < b.size(); });
#+end_src
~std::sort~ 并不保证等价元素原顺序， ~std::stable_sort~ 保证。
* lambda 的本质：匿名函数
[[id:6de72040-d0ad-4c4d-8e4f-c2a8da11e52a][labmda 表达式]] 具体可以参照这里对 lambda 表达式的描述。下面介绍C++中 lamda 的形式:
#+begin_src cpp
  [capture] (paramter) -> return_type {
    body
  }
#+end_src
常见比如:
#+begin_src cpp
  auto pred = [sz](const std::string &s) {
    return s.size() >= sz;
  }
#+end_src
这里的 ~[sz]~ 是传入的参数，表示按值捕获 (capture by value).

按值捕获的变量在 lambda 创建时复制进去:
#+begin_src cpp
  int x = 42;
  auto f = [x] {
    return x;
  };
  x = 0;
  std::cout << f(); // 42
#+end_src
也可以按引用捕获:
#+begin_src cpp
  int x = 42;
  auto f = [&x] {
    return x;
  };

  x = 0;
  std::cout << f(); // 0
#+end_src
引用捕获的核心风险是生命周期 (lifetime):
#+begin_src cpp
  auto make_pred() {
    int limie = 10;
    return [&limit](int x) {
      return x > limit;
    };
  } // 离开函数时，limit 已销毁，lambda 中的引用悬空
#+end_src
现代 C++ 的经验规则是:
#+begin_quote
lambda 捕获越简单越好；能按值捕获普通小对象，就不要默认按引用捕获。
#+end_quote
* 插入迭代器、流迭代器、反向迭代器
** 插入迭代器 (insert iterator)
三种插入迭代器:
#+begin_src cpp
  std::back_inserter(c); // 调用 c.push_back
  std::front_inserter(c); // 调用 c.push_front
  std::inserter(c, pos); // 调用 c.insert(pos, value)
#+end_src
比如:
#+begin_src cpp
  std::list<int> src{1, 2, 3};

  std::list<int> a;
  std::copy(src.begin(), src.end(), std::back_inserter(a));
  // a: 1 2 3
  std::list<int> b;
  std::copy(src.begin(), src.end(), std::front_inserter(b));
  // b: 3 2 1

  std::list<int> c;
  std::copy(src.begin(), src.end(), std::insert(c, c.begin()));
  // c: 1 2 3
#+end_src
我们可以把插入迭代器看成会自动插入新元素的迭代器。
** 流迭代器 (stream iterator)
输入流迭代器:
#+begin_src cpp
  std::istream_iterator<int> in(std::cin);
  std::istream_iterator<int> eof;
  std::vector<int> v(in, eof);
#+end_src
这会从标准输入一直读入 ~int~, 直到 EOF 或遇到非 ~int~ 输入。

输出流迭代器:
#+begin_src cpp
  std::ostream_iterator<int> out(std::cout, " ");
  std::copy(v.begin(), v.end(), out);
#+end_src
这会把 ~v~ 的元素输出到 ~cout~ ，每个元素后面加空格。

这体现了本章更抽象的一点: 算法操作的是序列，流也可以通过 stream iterator 被视为序列。
** 反向迭代器 (reverse iterator)
容器通常有:
#+begin_src cpp
  rbegin();
  rend();
  crbegin();
  crend();
#+end_src
比如:
#+begin_src cpp
  std::vector<int> v{1, 2, 3, 4};

  std::copy(v.rbegin(), v.rend(), std::ostream_iterator<int> (std::cout, " "));
#+end_src
输出是 ~4 3 2 1~

反向迭代器常用于从后往前查找:
#+begin_src cpp
  std::string path = "/home/user/main.cpp";

  auto slash = std::find(path.rbegin(), path.rend(), '/');
#+end_src
* 迭代器类别
部分算法有的容器无法使用.

| 类别                   | 能力                              |
|------------------------+-----------------------------------|
| input iterator         | 只读、单向、一次性读取           |
| ouput iterator         | 只写、单向                       |
| forward iterator       | 可多次遍历、单向                 |
| bidirectional iterator | 可 ~++~ 和 ~--~                   |
| random-access iterator | 可 ~+n~, ~-n~, ~it[n]~, 比较大小 |

这解释了很多现象:
#+begin_src cpp
  std::vector<int> v;
  std::sort(v.begin(), v.end()); // 可以
#+end_src
因为 ~vector~ 提供 random-access 能力。

而:
#+begin_src cpp
  std::list<int> lst;
  std::sort(lst.begin(), lst.end()); // 不可以
#+end_src
因为 ~list~ 只有 bidrectional iterator.

但是 ~list~ 自己提供成员函数: ~lst.sort()~ .

所以对于 ~std::list~ 和 ~std::forward_list~ 这类不提供随机存取迭代器的类型，优先使用它们自己的成员算法。

因为链表可以通过 relink nodes(改链接) 完成某些操作，不需要大量移动元素值。这通常比泛型算法更适合链表。
* 现代C++: ranges, views, span, execution policy
** C++20 ranges: 从 iterator pair 到 range object
#+begin_src cpp
  std::sort(v.begin(), v.end()); // 传统写法
  std::ranges::sort(v); // ranges 写法
#+end_src
传统写法需要手动传递一对 iterator, 而 ranges 写法可以直接接受一个 ranges. C++20 提供了 ~std::ranges~ 命名空间下的大多数受约束算法，这些算法可以接收 iterator-sentinel pair 或单个 range, 并支持 projection 和 pointer-to-member callabe, 很多返回类型也会返回更多执行过程中得到的消息。

比如, 按成员排序:
#+begin_src cpp
  struct Person {
    std::string name;
    int age{};
  };

  std::vector<Person> people {
    {"Alice", 20},
    {"Bob", 18},
    {"Carol", 25}
  };

  std::ranges::sort(people, {}, &Person::age);
#+end_src
~&Person::age~ 就是 projection(投影)。它的意思是，排序比较整个 ~Person~ 前，先把每个元素投影成 ~age~ 。

等价的传统写法是:
#+begin_src cpp
  std::sort(people.begin(), people.end(), [](const Person &a, const Person &b) {
    return a.age < b.age;
  });
#+end_src
** views: 惰性序列管道
~std::views~ 属于 ranges 生态。 ~views::filter~, ~views::transform~, ~views::take~ 通常是惰性的：它们并不立刻生成新容器，而是生成一个视图。

比如:
#+begin_src cpp
  std::vector<int> v{1, 2, 3, 4, 5, 6};

  auto evens =
      v
      | std::views::filter([](int x) { return x % 2 == 0; })
      | std::views::transform([](int x) { return x * x; });

  for (int x : evens) {
      std::cout << x << ' ';
  }
#+end_src
输出是:
#+begin_quote
4 16 36
#+end_quote
这里没有创建一个新的 ~vector<int>~, 只有当遍历 ~events~ 时， filter 和 transform 才逐个生效。 ranges algorithms 是 eager(立即执行) 的，而 ranges adaptors / views 是 lazy(惰性) 的，并且可以组合成管道。
** ~std::span~: 传递连续序列
C++20 的 ~std::span<T>~ 是一个非拥有连续序列视图。它可以指向数组、 ~std::array~, ~std::vector~ 的一段数据，但不拥有这些数据。它是可以引用一个 contiguous sequence of objects 的类模板。

#+begin_src cpp
  #include <span>

  int sum(std::span<const int> xs) {
    return std::accmulate(xs.begin(), xs.end(), 0);
  }
#+end_src
这样就不用限定传给 ~sum~ 的容器类型了。调用者可以传递:
#+begin_src cpp
  std::vector<int> v{1, 2, 3};
  std::array<int, 3> a{1, 2, 3};
  int raw[]{1, 2, 3};

  sum(v);
  sum(a);
  sum(raw);
#+end_src
** execution policy: 并行算法
C++17 引入 ~<execution>~, 部分算法可以接收 execution policy:
#+begin_src cpp
  #include <execution>

  std::sort(std::execution::pair, v.begin(), v.end());
#+end_src
* Generic Algorithms 总结
1. 泛型算法通过 iterator / ranges 工作，不直接依赖容器类型
2. 大多数算法使用 ~[first, last)~, 左闭右开
3. 算法通常不会改变容器的大小；真正删除元素要调用容器的 ~erase~
4. 写入目标必须足够大，不确定大小时用 ~std::back_inserter~
5. ~std::remove~, ~std::unique~ 只产生新的逻辑终点，不真正删除元素
6. 只读算法优先用 ~cbegin/cend~
7. ~std::sort~ 要求 random-access iterator, ~list~ 用成员函数 ~sort~
8. predicate 是返回可用于条件判断的 callable
9. lambda 是临时函数对象；谨慎引用捕获
10. 现代 C++ 优先考虑 ~ranges~ 和 projections
11. views 是惰性管道，不等于新容器
12. ~std::span~ 适合把连续序列作为函数传入

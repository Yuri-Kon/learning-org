* 如何理解继承
在 Java 中， ~extend~ 常常被理解成:

#+begin_example
子类继承父类实现，同时子类也是父类一种。
#+end_example
C++把这件事情拆分得更加细致。一个派生类继承基类时，实际上同时涉及至少四个不同层面:
1. 对象构成: 派生类对象内部包含一个基类子对象。
2. 实现复用: 派生类可以使用基类的成员函数和状态。
3. 类型关系: 派生对象能否被外部当作基类对象使用。
4. 动态多态: 派生类能否覆盖基类虚函数，并通过基类接口动态调用。


~public inheritance~ 和 ~private inheritance~ 的关键区别，主要发生在第三点:

#+begin_quote
这条 "Derived 是 Base" 的关系，是否属于 Derived 对外公开的类型接口。
#+end_quote
两者都会产生基类子对象，也都可以参与虚函数覆盖；因此它们并不是所谓“真的继承”与“假的继承”的区别。
#+begin_src cpp
  class Base{};

  class PublicDerived : public Base {};
  class PrivateDerived : private Base {};
#+end_src
~PublicDerived~ 和 ~PrivateDerived~ 内部都包含 ~Base~ 子对象。 C++ 标准也把私有基类视为真正的基类；例如 ~std::is_base_of_v<Base, PrivateDerived>~ 可以为 ~true~. 但只有公开且无歧义的继承才满足 ~std::derived_from~, 这正好体现了 “存在基类关系” 与 “构成公开子类型” 是两件不同是事情。
* ~public inheritance~: 公开承诺 “我是一种 Base”
#+begin_src cpp
  class Derived : public Base {};
#+end_src
公开继承表达的是:
#+begin_quote
~Derived~ 是一种 ~Base~, 因此任何只要求 ~Base~ 的代码，原则上都应当能够接受 ~Derived~ 。
#+end_quote
例如:
#+begin_src cpp
  #include <string>
  class Readable {
  public:
    virtual std::string read() = 0;
    virtual ~Readable() == default;
  };

  class FileReader : public Readable {
  public:
    std::string read() override {
      return "file contents";
    }
  };
  void print_contents(Readable &source) {
    // 这里只关心 "可读取"
    auto text  = source.read();
  }

  int main() {
    FileReader reader;
    print_contents(reader); // FileReader 作为 Readable 使用
    Readable &ref = reader; // 合法
    Readable *ptr = &reader; // 合法
  }
#+end_src
这里 ~FileReader~ 对外公开承诺:
#+begin_quote
我满足 ~Readable~ 的接口和语义约束。
#+end_quote

公开继承不仅保留基类的公开成员可见性，也使派生类到基类的隐式转换在普通外部代码中可用。C++标准规定，公开基类的 ~public~ 成员在派生类中仍为 ~public~, ~protected~ 成员仍为 ~protected~; 当基类在当前位置可访问时，派生类指针可以隐式转换为基类指针。
** public inheritance 不只是 "复用代码"

最重要的是类型设计思想。

假设有:

#+begin_src cpp
  class ResizableBuffer {
  public:
    virtual void resize(std::size_t new_size) = 0;
    virtual std::size_t size() const noexcept = 0;
    virtual ~ResizableBuffer() = default;
  };
#+end_src

现在写:
#+begin_src cpp
  class FixedBuffer : public ResizableBuffer{
  public:
    void resize(std::size_t new_size) override {
      throw std::logic_error{"FixedBuffer cannot resize"};
    }
    std::size_t size() const noexcept {
      return 1024;
    }
  };
#+end_src
语法上这样是合法的，但设计上可能有问题:

任何接受 ~ResizableBuffer&~ 的代码都有理由假设:
#+begin_src cpp
  void prepare(ResizableBuffer& buffer) {
    buffer.resize(4096);
    // 后续代码依赖 resize 成功后的状态
  }
#+end_src
如果加入 ~FixedBuffer~ 后，核心操作永远失败，那么 ~FixedBuffer~ 虽然继承了接口，却没有实际上履行 ~ResiableBuffer~ 的语义契约。

因此公开继承的标准并不是语法上的 _派生类是否能够复用基类代码_, 而是语义上的:

#+begin_quote
派生类能否在语义上代替基类？
#+end_quote

这就是可替换性思想。这并不是C++独有的，而是面向接口和类型设计中的通用原则。
** public inheritance 是稳定的外部 API

* lambda 演算 & lambda 表达式
:PROPERTIES:
:CUSTOM_ID: lambda-演算-lambda-表达式
:END:
该文件作为对于 lambda 表达式的补充。

** 概览
:PROPERTIES:
:CUSTOM_ID: 概览
:END:
我们可以把 =lambda calculus= (λ 演算) 理解为：一种把 “计算” 还原为 “函数定义” 和 “函数应用” 的极简数学语言。它和图灵机一样，是20世纪30年代提出的计算哦模型，用来回答 “什么叫可计算” 这个根本问题。

\(\lambda\) 演算的提出者是 Alonzo Church.它最初来自数理逻辑研究，目标是用一种形式系统描述函数、函数应用以及可计算性。而在 OCaml 中，匿名函数之所以也叫 =lambda expressions= ，是因为这个术语来自 =lambda calculus= ；在 \(\lambda\) 演算中， OCaml 的 =func x -> e= 会写成 \(\lambda x.e\)

** lambda 演算的核心
:PROPERTIES:
:CUSTOM_ID: lambda-演算的核心
:END:
基本只需要三种东西。

第一种是变量，例如：

#+begin_src text
x
y
n
#+end_src

第二种是函数抽象，也就是定义一个匿名函数:

\[
\lambda x. x
\]

这表示 “一个接受参数 =x= ，并返回 =x= 的函数”。它在 OCaml 中大概对应:

#+begin_src ocaml
fun x -> x
#+end_src

第三种是函数应用，也就是把函数作用到参数上:

\[
(\lambda x. x) 3
\]

在 OCaml 中大致对应:

#+begin_src ocaml
(fun x -> x) 3
#+end_src

这会得到:

#+begin_src ocaml
3
#+end_src

所以 \(\lambda\) 演算的最基本的思想是: *函数本身就是值* ，计算就是把函数应用到参数，然后进行替换和化简。

** 规约规则
:PROPERTIES:
:CUSTOM_ID: 规约规则
:END:
它最重要的规约规则是 \(\beta\) -reduction ，可以先理解为 “把实参带入函数体”。

例如：

\[
(\labmda x. x + 1) 3
\]

化简为:

#+begin_src text
3 + 1
#+end_src

再得到:

#+begin_src text
4
#+end_src

对应 OCaml 中是:

#+begin_src ocaml
(fun x -> x + 1) 3
#+end_src

也就是说，对于 \((\lambda x. e) v\) 大致可以化简为：*e 中所有自由出现的 x 都替换为 v*

比如：\((\lambda x. x) 5\) 的结果是25

#+begin_quote
[!TIP] 这就是为什么函数式编程里经常强调 “表达式求值”，因为从 \(\lambda\) 演算视角来看，计算就是表达式一步步化简。
#+end_quote

在 OCaml 中，lambda expression 里的直接形式就是：

#+begin_src ocaml
fun 参数 -> 函数体
#+end_src

可以直接应用，也可以绑定到名字上。因此可以写为:

#+begin_src ocaml
let inc = fun x -> x + 1
#+end_src

和下面这种一般写法等价:

#+begin_src ocaml
let inc x = x + 1
#+end_src

匿名函数和具名函数虽然在语法上不同，但是在语义上可以等价。

#+begin_quote
[!IMPORTANT] 因此，我们可以把 =let inc x = x + 1= 理解为一种语法糖，它偏向于 =let inc = fun x -> x + 1=。这点非常重要，因为函数名 =inc= 本身只是一个绑定，真正的函数值是 =fun x -> x + 1=
#+end_quote

因此在 OCaml 中，函数和整数、列表、字符串一样，都是值。也因此可以作为参数传递、作为结果返回。

例如，高阶函数:

#+begin_src ocaml
let apply_twice f x = f (f x)
#+end_src

它的值和类型为:

#+begin_src ocaml
val apply_twice : ('a -> 'a) -> 'a -> 'a = <fun>
#+end_src

我们可以这样调用:

#+begin_example
apply_twice (fun x -> x + 1) 10
#+end_example

得到的结果是 =12= 。这里， =fun x -> x + 1= 就是一个匿名函数，当作了一个参数传给 =apply_twice= 。

在比如列表处理:

#+begin_src ocaml
List.map (fun x -> x * x) [1; 2; 3; 4]
#+end_src

结果是:

#+begin_src ocaml
- : int list = [1; 4; 9; 16]
#+end_src

这里的意思是：把匿名函数 =fun x -> x + 1= 应用到列表里的每个元素上面。

从 \(\lambda\) 演算上看，=List.map= 接收一个函数，然后把它应用到一组值上。这个思想就是函数式编程的核心之一。

** 多参函数与 lambda 演算
:PROPERTIES:
:CUSTOM_ID: 多参函数与-lambda-演算
:END:
OCaml 中的多参函数也和 \(\lambda\) 的关系很深。比如:

#+begin_src ocaml
let add x y = x + y
#+end_src

可以理解为:

#+begin_src ocaml
let add = fun x -> fun y -> x + y
#+end_src

其类型为:

#+begin_src ocaml
val add : int -> int -> int = <fun>
#+end_src

#+begin_quote
[!tip] 这个类型其实是 *右结合* ，也就是 =int -> (int -> int)= ，意思是： =add= 接收一个 =int= ，返回一个新的函数；这个新的函数再接收一个 =int= ，最后返回 =int= 。
#+end_quote

所以对于 =add 1 2= 可以理解为:

#+begin_src ocaml
(add 1) 2
#+end_src

先执行:

#+begin_src ocaml
add 1
#+end_src

得到:

#+begin_src ocaml
fun y -> 1 + y
#+end_src

然后再应用到 =2=:

#+begin_src ocaml
(fun y -> 1 + y) 2
#+end_src

得到结果 =3= 。

上面就是所谓的 *柯里化（currying）* 。它和 Haskell Curry 有关，但思想与 \(\lambda\) 演算中 “函数只接收一个参数，多参数函数可以表示为返回函数的函数” 密切相关。

也因此， OCaml 里的函数类型:

#+begin_src ocaml
'a -> 'b -> 'c
#+end_src

并不是说 “真正接收两个参数的函数类型”，更确切地说，它是：

#+begin_src ocaml
'a -> ('b -> 'c)
#+end_src

这正是 \(\lambda\) 演算风格在 OCaml 中的直接体现。

** lambda 与 =let= 的关系
:PROPERTIES:
:CUSTOM_ID: lambda-与-let-的关系
:END:
再看 =let= 。在 OCaml 中，

#+begin_src ocaml
let x = 3 in x + 1
#+end_src

从 \(\lambda\) 演算的角度可以理解为:

#+begin_src ocaml
(fun x -> x + 1) 3
#+end_src

从这个角度出发，=let= 绑定本质上也可以看成 *定义一个匿名函数并立刻使用* 。也因此，=let= expression 可以被看成 anonymous function （匿名函数）的语法糖。

这也是为什么 OCaml 中下面两个东西关系很密切:

- =let x = e1 in e2=
- =(fun x -> e2) e1=

它们都表达 “先得到一个值，然后在后续表达式中用一个名字引用它” 。

不过需要注意， OCaml 中还有类型系统、模式匹配、副作用、异常、对象系统等很多 \(\lambda\) 本身没有的东西。\(\lambda\) 演算是一个极简的核心模型， OCaml 是一门完整的工业级语言。OCaml 官方也将 OCaml 描述为兼具函数式、静态类型、模块系统和对象系统等特性的通用语言。

** 其他高级语言中的 lambda 或匿名函数
:PROPERTIES:
:CUSTOM_ID: 其他高级语言中的-lambda-或匿名函数
:END:
其他高级语言中也大量使用 lambda 或匿名函数，只是语法不同。

Python 里有:

#+begin_src python
lambda x: x + 1
#+end_src

常见用法是:

#+begin_src python
list(map(lambda x: x * x), [1, 2, 3])
#+end_src

Java 8 之后也支持 lambda 表达式:

#+begin_src java
x -> x + 1
#+end_src

常见于 Stream API:

#+begin_src java
List.of(1, 2, 3).stream()
  .map(x -> x * x)
  .toList()
#+end_src

C++ 中也有 lambda:

#+begin_src cpp
  auto square = [](int x) {return x * x; };
#+end_src

Haskell 中更接近 \(\lambda\) 演算本身:

#+begin_src haskell
\x -> x + 1
#+end_src

其中，=\= 可以看作 ASCII 形式的 \(\lambda\) 。

这些语言里的 lambda 表达式，本质上都继承了同一个思想：*可以在需要函数的地方直接写一个函数值，而不一定先给它命名* 。

但不同语言的 lambda 能力差异很大。 OCaml 、 Haskell 、 =F#= 这类函数式语言通常把函数作为一等值， lambda 、高阶函数、柯里化、类型推断都非常自然。 Python 、JavaScript 也把函数当成值，但是类型系统和求值模型不同。 Java 、 C++ 的 lambda 更多是为回调、集合处理、并发任务和函数式接口等场景服务。

** 小结
:PROPERTIES:
:CUSTOM_ID: 小结
:END:
回到我们学习 OCaml 时最该抓住的点:

#+begin_src ocaml
fun x -> e
#+end_src

就是 \(\lambda\) 演算中的:

\[
\lambda x. e
\]

函数应用:

#+begin_src ocaml
f x
#+end_src

就是 \(\lambda\) 演算中的:

\[
\lambda x
\]

多参数函数:

#+begin_src ocaml
fun x y -> e
#+end_src

可以理解为:

#+begin_src ocaml
fun x -> fun y -> e
#+end_src

也就是:

\[
\lambda x. \lambda y. e
\]

=let= 绑定:

#+begin_src ocaml
let x = e1 in e2
#+end_src

可以理解为:

#+begin_src ocaml
(fun x -> e2) e1
#+end_src

也就是：

\[
(\lambda x. e2) e1
\]

#+begin_quote
[!summary] 总结 *OCaml 中 “函数是一等值”、“高阶函数”、“匿名函数”、“柯里化”、“let 绑定的表达式化理解”，都可以追溯到 \(\lambda\) 演算把计算视为函数抽象与函数应用的思想。*
#+end_quote

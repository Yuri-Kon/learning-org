有一个基础认知:

#+begin_quote
~config.yaml~ 并不是 Mihomo 的全部运行环境。
#+end_quote

更完整的模型应该是:

#+begin_example
Mihomo process
|
|-- HomoDir
|   |-- config.yaml
|   |-- proxy provider files
|   |-- rule provider files
|   |-- cache.db
|   |-- GeoIP / GeoSite
|   |-- external-ui
|
|-- startup arguments
|   |
|   |-- -d
|   |-- -f
|   |-- ...
|   
|-- runtime state
    |-- proxy groups
    |-- selected proxies
    |-- providers
    |-- connections
    |-- DNS / fake-ip state
#+end_example

也就是说，在以后设计 mihomgr 的时候，不能只记录:

#+begin_src python
  config_path: Path
#+end_src

还必须理解:

#+begin_src python
  home_dir: Path
  config_path: Path
#+end_src


它们是两个不同的概念。

-----

* ~-d~ 和 ~-f~

当前 Mihomo 源码里直接定义了这些参数:

#+begin_example
-d set configuration directory
-f specify configuration file
-t test cofiguration and exit
-v show current version
#+end_example

也分别支持 ~CLASH_MOHE_DIR~ 和 ~CLASH_CONFIG_FILE~ 环境变量。

因此，当执行 ~mihomo -d /etc/mihomo~ 时，其意思不仅是简单的“读取 ~/etc/mihomo/config.yaml~ ”，更准确地说是:

#+begin_quote
将 ~/etc/mihomo~ 设置成 Mihomo 的 HomeDir
#+end_quote

如果没有额外提供 ~-f~, Mihomo 才会使用 ~HomeDir/config.yaml~ 作为配置文件。

* ~-f~ 与 HomeDir

现在考虑:

#+begin_src bash
  mihomo -d /etc/mihomo -f /tmp/test.yaml
#+end_src

这时候， HomeDir 是 ~/etc/mihomo~, 配置文件是 ~/tmp/test.yaml~ 。也就是说，配置文件不再 HomeDir 中也是完全被允许的。

此外还有一个比较重要的性质:

#+begin_quote
~-f~ 改变的是主配置文件的位置， ~-d~ 改变的是 Mihomo 运行环境的根目录。
#+end_quote


* HomeDir 的作用

在 mihomo 中，HomeDir 通常十分重要。因为有大量的“相对路径”不是简单地相对于 ~config.yaml~ 的位置。

例如下面的配置:

#+begin_src yaml
  proxy-providers:
    airport:
      type: http
      url: ...
      path: ./proxy_providers/airport.yaml
#+end_src

这里的 ~./proxy_providers/airport.yaml~ 是受 Mihomo HomeDir 管理的路径。 Proxy Provider 的 ~path~ 默认只能位于 HomeDir 中；需要访问 HomeDir 以外的位置时，需要通过 ~SAFE_PATHS~ 显式加入允许路径。

假设我们通过 ~mihomo -d /etc/mihomo~ 进行配置:

#+begin_src yaml
  proxy-providers:
    airport:
      path: ./providers/airport.yaml
#+end_src

那么实际位置是: ~/etc/mihomo/providers/airport.yaml~ 。


* ~mihomo -t~

~mihomo -t~ 的意思是: test configuration and exit

它会进入配置解析流程。如果解析失败， ~exit code != 0~. 解析成功就会显示 ~configuration file ... test is successful~ ，然后退出。

但是有一个问题，需要注意： ~mihomo -t -f candidate.yaml~  这里没有指定 HomeDir, 因此会使用它自己默认的 HomeDir, 这就与我们的配置产生冲突。于是，我们应该显式指定 ~-d~ 。

此外， ~mihomo -t~ 非常适合成为 ~ConfigValidator~ 的底层机制。但是有一个重要的区别:

- YAML parser: 只能证明 YAML 是合法结构
- ~mihomo -t~: 证明 Mihomo 能够解析这个配置


因此， ~mihomgr~ 的最终校验应该交给 ~mihomo~ 来执行。

但与此同时， ~mihomo~ 也不是我们需要的唯一校验。

可以把校验分成三层来解析。

** 第一层: 格式解析

也就是验证 YAML 格式是否正确。负责发现缩进错误、非法的 YAML 、错误的数据类型结构。

** 第二层: mihomgr 领域验证

例如:

由 Subscription "airport-a" 会生成一个 ~proxy-provider airport-a~, 那么 mihomgr 可以提前检查:

- subscription 是否存在
- provider 名是否冲突
- profile 引用的 subscription 是否存在
- secret 环境变量是否存在
- 生成文件目标是否允许


而这些并不属于 mihomo 的职责。

** 第三层: mihomo 权威验证

最后才会调用:

#+begin_src bash
  mihomo -t -d ... -f ...
#+end_src

来确认 mihomo 自己认为这个配置可以被加载。

因此未来可以形成:

#+begin_example
render
|
structural validation
|
mihomgr semantic validation
|
miho validation
|
ValidateConfig
#+end_example

实际上是天然对应的。

-----

* 配置内部形成了一张引用图

#+begin_src yaml
  proxy-providers:
    airport:
      type: http
      url: ...
      path: ./providers/airport.yaml

  proxy-groups:
    PROXY:
      type: select
      use:
        - airport

  rules:
    - DOMAIN-SUFFIX,github.com,PROXY
    - MATCH,DIRECT
#+end_src

这三个 section 其实是互相关联的:

#+begin_example
Proxy Provider
airport
|
|
Proxy Group
PROXY
|
|
Rule
github.com -> PROXY
#+end_example

这里需要区分 ~proxies:~ 和 ~use:~ :

- ~proxies~: 引用具体的 proxy 或其他 proxy-group
- ~use~: 引用 proxy-provider


* 重新加载配置

有两条很重要的路线。一条是进程信号: ~SIGHUP~, Mihomo 源码明确监听 ~SIGHUP~ 。

另一种是 ~PUT /configs~, 官方 API 定义:

- ~GET /configs~: 获取当前基础运行配置
- ~PUT /configs?force=true~: 重载配置
- ~PATCH /configs~: 修改部分运行配置


这里我们要明确区分 ~Reload~ 和 ~Patch runtime configuration~, 例如:

#+begin_src http
  PATCH /configs
  {
    "mixted-port": 7891
  }
#+end_src

其实会直接修改运行配置。而 mihomgr 的 ~config apply~ 不应该退化为 “大量 PATCH”。我们希望它尽可能保持重载。


* 总结

1. Mihomo 的 ConfigFile 和 HomeDir 是两个不同的概念
2. ~-d~ 设置 HomeDir, ~-f~ 指定主配置文件
3. 不指定 ~-f~ 时，Mihomo 默认读取 ~HomeDir/config.yaml~
4. Provider 等相对资源路径通常以 HomeDir 为基础解析
5. ~SAFE_PATHS~ 扩展 Mihomo 允许访问的安全文件路径
6. ~mihomo -t~ 是权威的 Mihomo 配置解析检查，但 mihomgr 仍应在其之前进行自己的结构引用检查。
7. mihomgr 验证 candidate 时，应尽量使用与实际服务相同的 HomeDir: ~mihomo -t -d <runtime-home> -f <candidate>~
8. 配置文件实际上形成了一张引用图
9. ~mihomgr config apply~ 应追求磁盘期望状态与运行状态保持一致，而不是依靠大量 ~PATCH /configs~ 临时改变运行状态
